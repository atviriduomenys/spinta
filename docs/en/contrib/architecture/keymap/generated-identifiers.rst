#####################
Generated identifiers
#####################

Generated identifiers are internal `id` values that Spinta *generates*
itself, rather than taking them from the data source — the value side of
the keymap (`KeyMap.encode()`, see :doc:`/contrib/architecture/keymap/index`).
They are used whenever the external key is unreliable, composite or
absent, and whenever a pushed object must get a globally unique
identifier.

Generation
**********

- Keymap encoding — `KeyMap.encode(name, value)` generates
  a `uuid.uuid4()` internal key for every new external value
  (e.g. `spinta/datasets/keymaps/sqlalchemy.py`) — see
  :doc:`/contrib/architecture/keymap/index` for the mapping table
  layout.
- Object ids — `commands.gen_object_id(Context, Backend, Model)`
  (implemented in `spinta/backends/__init__.py`) returns
  `str(uuid.uuid4())`; backend and model can overload it, e.g. the
  `base32` id type encodes values instead of generating
  (see `spinta/types/pk/`).
- Changelog and revisions — `_txn` transaction ids and `_revision`
  object versions are UUIDs generated by the internal backend (e.g.
  PostgreSQL and memory backends in `spinta/backends/*/components.py`).
- Clients and tokens — client ids and access token `jti` claims are
  `uuid.uuid4()` as well (`spinta/auth.py`, `spinta/cli/auth.py`).

Identifiers appear as the reserved `_id` property of every model (see
:doc:`/contrib/architecture/manifests/logical/properties`) and are
exposed to clients as UAPI resources' `_id` (see `UAPI`_).

.. _UAPI: https://ivpk.github.io/uapi

External specifications
***********************

- UAPI (https://github.com/atviriduomenys/uapi, local extract
  `.tmp/sources/uapi/UAPI.md`): "Global object identifiers are assigned
  to real or fictional world entities" — global identifiers must be
  unique across the whole data space, all local identifiers must be
  mapped to a single global identifier, and objects are identified
  only by global identifiers (with `_id`). UUID format is
  recommended. Spinta's keymap-encoded ids are the implementation of
  that global identifier.
- DSA (https://ivpk.github.io/dsa/, local extract
  `.tmp/sources/dsa/DSA.md`): the reserved `_id` property must be
  unique across the whole data space, formed from `model.ref` or taken
  directly from `_id.source`; `base32` typed ids are Base32-encoded
  values. Maturity level 4 (`L400`, "Identified") requires
  `model.ref`/`property.ref` to be filled — that is when stable,
  generated identifiers become used.
