# ADR-0004: An empty declared identifier is not described in OAS

- **Status:** Accepted
- **Date:** 2026-09-17
- **Related:** [#2004](https://github.com/atviriduomenys/spinta/issues/2004),
  [PR #2012](https://github.com/atviriduomenys/spinta/pull/2012)

## Context

A model can declare its own `_id`. The object identifier is then not a UUID
generated by Spinta but the value of the model's primary key:

- `base32`: the key encoded as Base32 without `=` padding (`encode_base32`);
  `kodas = "LT"` → `_id = "JRKA"`, reached at `/Salis/=JRKA`;
- `string`: the key value, reached through `=` when the key is not composite
  (`/Salis/=LT`, see `is_accessible_by_equals_sign`).

The specification gives such an identifier a pattern:

| Where | Pattern |
|---|---|
| `base32` value in a response | `BASE32_VALUE_PATTERN`: Base32 of a valid length |
| `base32` `{id}` in a request | `BASE32_ID_PATTERN`: `=` and Base32 of a valid length, up to 513 characters |
| `string` `{id}` in a request | `DECLARED_ID_PATTERN` / `EQUALS_ID_PATTERN`: one path segment, 1–512 characters |

All of them require **at least one character**. Copilot reviews pointed out
several times that Spinta technically accepts an empty key: `encode_base32("")`
returns `""` and `String.load("")` succeeds, so an object with an empty source
key would be answered with `_id: ""` and reached at `/=`, while the
specification rejects both.

## Decision

An empty declared identifier is **not described**: the patterns keep requiring
at least one character, and the suggestion to relax them is declined.

- An empty primary key is broken source data, not an identifier a data service
  offers its users.
- `/=` is not a meaningful object address; no client can use it on purpose.
- The specification is the service contract. Allowing an empty value would let
  `/=` requests through the gateway and stop the schema from saying that an
  identifier is a value.

## Alternatives considered

1. **Make the last Base32 group and the `string` length optional, so an empty
   value passes.** The specification would match what Spinta technically
   accepts, but would make broken data part of the service and let `/=`
   requests through the gateway. Rejected.
2. **Reject an empty key in Spinta itself** (`Base32.load`, `String.load` for a
   declared `_id`). A more accurate fix at the data level, but it changes how
   Spinta treats existing data and is outside OAS generation. Not done; may be
   a separate task.

## Consequences

- An object with an empty primary key in the source would be rejected by gateway
  response validation and could not be reached through the gateway. This is a
  data quality issue, fixed in the source.
- A reviewer's suggestion to relax `BASE32_VALUE_PATTERN`, `BASE32_ID_PATTERN`,
  `DECLARED_ID_PATTERN` or `EQUALS_ID_PATTERN` for an empty value is declined
  with a reference to this ADR.
